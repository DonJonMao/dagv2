# 剩余求解驱动的记忆推理：详细设计

版本：设计 v1，2026-10-10。代码基线：`f6a172123ca05ec4fdc0463b94cd3a91253bfbbb`。实现目标：`dagbt_residual_memory_v1`。工作分支：`feat/residual-memory-reasoning`。

本文是待实施的方法设计，不是已完成算法的实验报告。主线是：**始终维护原问题还缺哪些会改变所需答案的信息，以这些缺口驱动问题分解、原文桥接、联合阅读与停止。**

## 1. 科学问题与方法目标

长期记忆任务的困难，不仅是相关历史没有被召回，还包括尚不知道该找什么、局部历史必须组合才能解释，以及一些初始计划中的问题在新证据出现后已经不必继续求解。

研究问题是：**如何通过有来源的中间结论，逐步消除原问题中真正影响答案的未决部分，并避免为已经不影响输出的信息继续支付取证和阅读成本？**

方法不以候选池扩大、检索轮数增长或模型自信上升作为完成标志。它以原始输出要求是否已被当前有效证据确定为目标。DAG 是剩余任务的计算结构；无评分桥接是获取未决变量证据的操作；节点模型把原文解释为可追溯的变量绑定；终端输出是剩余任务被求出的结果。

采用五项已确定的边界：不增加原问题额外 dense 通路；不使用 reranker 或四项差分；普通取证围绕当前已接地的子问题；节点联合阅读同时产生答案与来源，不另设全量 LLM mapping；终端完成回答，不再运行全局 FinalSelector 和独立 Reader 重答。已有实体、时间、来源校验与反证处理继续保留。[R1–R4]

## 2. 首先确定“用户到底要求输出什么”

### 2.1 输出要求先于停止条件

同一批历史，对不同问题有不同的充分性。例如，下面三种请求不能共用同一个停止规则：

| 请求 | 最终必须确定的内容 |
|---|---|
| 方案是否可采用？ | 一个明确的可采用性判断 |
| 不可采用时，指出一个决定性阻碍即可 | 判断，以及至少一个有证据支持且足以否决的原因 |
| 列出所有未满足的采用条件 | 判断，以及完整的未满足条件集合 |

发现一项必要条件失败，足以回答第一种请求，通常也能回答第二种；不一定足以回答第三种。发现另一个可能原因，也不应使第二种请求无休止地追求唯一原因。

### 2.2 输出契约

一次规划定义输出契约 `output_contract`，包含需要的语义字段、输出类型、数量词、时间/实体范围、解释要求，以及明确的终端节点。程序不把自然语言字符串逐字相同当成答案相同；实体、数值、布尔值和集合采用类型化规范表示。

如果采用条件来自历史，规划器只能先创建“找出适用规则”的需求，不能在未读原文时自行假定条件只有三项。规则取得来源后，才能具体化求解表达式。用户要求输出什么始终固定；内部规则的细化必须有出处，并版本化记录。

开放式建议、任意自然语言质量判断，没有自动可枚举的完备答案空间。这类任务保留节点式语义求解，但标为 `semantic_assessment`，不得宣称取得了下文的精确答案不变证书。

## 3. 贯穿全程的状态

用下列符号描述整个过程，各符号只承担一种含义。

| 符号 | 含义 |
|---|---|
| Q | 用户当前问题及固定输出要求 |
| F | 将任务变量映射到所需语义结果的类型化求解表达式 |
| X | 任务变量集合，包括实体绑定、规则、时间条件和比较结果 |
| Γ_t | 第 t 次更新时，仍有效的带来源事实及其约束 |
| θ_t | 从 Γ_t 得到的已确定变量绑定 |
| Ω_t | 与当前有效证据一致的未决变量合法取值集合，或其保守外包络 |
| F_t | 在 θ_t 下部分求值后的剩余求解表达式 |
| C_t | 已发现的原文及其读取/未读取状态 |
| H_t | 尚可执行的、归属于当前缺口的检索与阅读状态 |
| B_t | 剩余实际资源预算 |

核心更新写作：

$$F_t=\operatorname{Reduce}(F,\Gamma_t). \tag{1}$$

在只有确定绑定、不涉及其他约束的情形，它就是 F 在 θ_t 下的部分求值。Γ_t 比单一答案表多保留出处、条件、依赖版本和相互关系，因此能处理来源撤销及共享变量。

主控状态为 `(F_t, Γ_t, C_t, H_t, B_t)`。缓存、日志和候选池不是替代性的求解目标。新增证据必须更新这个状态，才能影响后续动作。

## 4. 数学语义：什么情况下可以停止

### 4.1 已确定、未确定与冲突必须分开

布尔变量未知时，其可取值为 `{false, true}`，不是 false。没有搜索到证据、请求失败、协议不合法和模型没有回答，都不能缩成 false。

有限类别变量需要完整域声明。开放实体域中，“目前找到一个名字”不表示其他名字不存在，应保留尚未排除的值类；开放数值可以使用带单位的区间。不同引用里的同一个变量必须共享身份，不能独立采样成互相矛盾的取值。

若有效约束相互冲突导致 Ω_t 为空，应报告不一致并处理来源，不能利用空集合上的全称命题把任意答案判定为有效。

### 4.2 结果集合与停止证书

对具有确定语义函数的任务，可能输出集合为：

$$\mathcal Y_t=\{F(\omega):\omega\in\Omega_t\}. \tag{2}$$

当 Ω_t 非空且结果集合只有一个值时，未决变量不再影响这项输出：

$$\Omega_t\ne\varnothing\quad\land\quad |\mathcal Y_t|=1. \tag{3}$$

实际实现可以计算一个安全外包络 Ŷ_t，只要真实可能结果包含于其中。外包络为单值时可认证；外包络多值时只能说明尚不能认证。有限枚举超出资源上限时返回 `indeterminate`，不能删掉未枚举分支来制造单值。这个方向借用抽象解释的保守计算原则，不把该原则本身作为新颖性。[T1]

### 4.3 “给一个原因”不要求所有解释完全一致

当输出允许多个合法答案时，用输出关系 A_Q(y,ω) 表示答案 y 是否满足状态 ω 下的用户要求。候选输出可发布的条件是：

$$\Omega_t\ne\varnothing\quad\land\quad \forall\omega\in\Omega_t,\ A_Q(y,\omega)=\mathrm{true}. \tag{4}$$

例如，已确认删除条件失败，y 可以是“不能采用；删除条件失败”。即使还有另一项条件也可能失败，该输出仍然满足“指出一个决定性原因”的要求。若要求“列出全部失败项”，就必须确定完整集合。

输出关系由受支持的操作类型和输出契约确定，不能交给另一个自由文本评分器猜测。`unknown`、拒答或空答案不被算作成功完成任务；它们是明确的未完成结果。

### 4.4 保证范围

上述证书保证的是：在给定任务语义、正确的来源解释、完备或保守的取值范围内，尚未求解的部分不会改变所发布输出。它不保证 LLM 没有误解原文，不保证初始分解必然正确，也不保证语料中绝无未读反证。所有已读且相关的冲突必须处理，不能为了早停隐藏它们。[T3]

## 5. DAG 不再等于“所有规划节点都必须执行”

### 5.1 区分取证节点与计算节点

取证节点负责“从历史确认一个事实”，需要子问题 dense、必要的桥接和联合阅读。计算节点负责对已确认的事实做确定性组合，例如 AND、OR、比较、集合构造；能由程序计算的结果，不再调用 LLM。

语义综合节点用于无法通过支持算子直接求值的内容，在终端执行一次所需综合。它不伪装成确定性的形式证明，也不在已完成的终端后追加一次 Reader。

### 5.2 当前前提是否必要，由剩余表达式决定

设可采用性为 F=A∧D∧O。发现 D=false 后：

$$F_t=A\land\mathrm{false}\land O=\mathrm{false}. \tag{5}$$

对于仅要求判定、或判定加一个否决原因的任务，A 和 O 不再是完成当前输出的必要求解项。它们不是“假”，也不是“永久不相关”，只是这次输出已不需要继续确认。

相反，若输出包括所有失败项，则求解式还包含 `Failures(A,D,O)`，A 和 O 仍在剩余任务中。AND/OR 在这里表示问题本身的逻辑，不是为了防止算法出错而人为加的剪枝阈值。

对于实体链，必须先确认被查询对象，再构造后继取证。例如负责人 x 未绑定时，不能猜一个 x 发起项目查询。对一般语义节点，仍须满足真正需要的输入；对布尔计算节点，不能保留旧的“一律等待所有父节点 supported”规则，从而抵消短路求值。

### 5.3 实际依赖与共享

同一个事实在多个地方出现时共享变量和来源状态，避免重复求解。任务依赖描述可执行性，来源支持关系描述结论为何成立，发现路径描述怎样取得原文，三者不能混为一种边。

有限域精确后端应尊重联合约束。以 x=y 为例，不能由于单变量局部扰动不可行，就判定 x、y 都无用；观察其中一个可能足以确定输出。第一版保守的结构依赖集合可以多保留需求，但不得漏掉可能改变结果的需求。

## 6. 原文桥接由剩余需求驱动

### 6.1 一次取证的输入

从 F_t 提取当前仍有作用、且参数可接地的需求 q_i。第一次访问该需求时执行一次 dense，得到原文起点。没有独立的原问题基线。

桥接状态为 `(需求身份, 初始起点, 当前线索, 前序原文ID, 查询绑定版本)`。所有参数均来自当前问题、已支持结论或真实原文；检索指令可以说明缺失关系，但不得把尚未确定的答案写成事实。

### 6.2 条件检索与子候选池

将当前子问题、尚未解决的关系、当前线索全文和本分支前序原文确定性组成 embedding 输入，再到可见记忆库检索。每条边只做 embedding 和向量查询，不调用 reranker，也不调用 LLM 对候选或分支逐一评分。

每个初始起点对应一个子候选池，记录由该起点各分支发现的原文。候选池允许重合；最终联合读取时，同一原文正文只出现一次。根归属用于追溯，不构成语义隔离，不阻止不同池的原文共同支持同一个结论。

检索仍有向量排序。去掉 reranker 不等于取消排序，也不意味着所有返回内容都正确。只排除当前路径中的重复记忆和相同查询状态，不能因为一份文档已被其他起点发现，就取消其不同背景下的桥接机会。[R2]

### 6.3 不再先无条件扩满，再一次性理解

执行节奏改为：**读取当前一批候选 → 更新事实与剩余需求 → 仅为仍有作用的缺口扩展 → 再读新增材料。**

节点阅读同时返回变量绑定、出处、适用范围、矛盾和未解项。程序验证引用、类型、范围及依赖；可复用已有来源片段工具，不必复用旧的逐批独立 LLM mapping。

同一个节点可能读取多批，但不会为每个子候选池单独调用 Reader。第二批输入包括当前问题、必要的已读支持片段与新增原文，不无条件重发全题累积历史。新旧原文需共同解释时，必须重现相关原文，不能只给未经出处绑定的摘要。

联合读取的分批由实际上下文容量决定。完整原文装不下时，明确待读队列和未读范围；不能静默截断后宣称所有来源都已评估。极长单条记录可采用保留位置和相邻上下文的显式原文分窗，不做隐藏摘要或截断。

### 6.4 与剩余问题无关，不等于文档无用

停止为一个已被逻辑消去的条件继续专门取证，不等于删除它相关的历史。某份旁支材料仍可能提供当前活跃缺口的桥接线索；已经读到的反证也必须触发更新。剪去的是特定目标的无必要工作，不是把整个记忆类型永久过滤。

## 7. 调度与成本：严格到什么程度

### 7.1 第一版必须实现的决策

每次有效阅读后立刻化简 F_t；已经不影响输出的目标不再启动新的取证；共享事实尽量一次解释、多处使用；参数未绑定的检索暂不执行；终端证书成立且相关核验通过后停止；预算耗尽而答案未确定时返回未完成。

这些动作由求解语义决定，而不是 k、深度阈值、相似度权重或 LLM 自信分数决定。

### 7.2 不能把未知检索效果写成已知最优策略

多个活跃缺口之间，第一版采用固定、可复现的拓扑可执行顺序；同一缺口的桥接采用现有无评分检索的稳定轮换与本地向量排名。它是实施基线，不是全局最优调度定理。只有活跃集与停止由形式语义控制，不能把一个轮换规则命名成贝尔曼最优策略。

检索宽度、上下文容量、HTTP重试和全题预算仍是实际资源条件，但不再定义任务何时被解决。正确性测试应在固定预算下对比关闭/开启剩余求值，区分逻辑节省与单纯减少投入。

### 7.3 统一成本目标与后续可研究的调度

动作 a 包含实际的检索和按计划发生的联合阅读，其代价 c(a,h) 在状态 h 下记录真实模型输入、输出、设备时间等。选择一个明确的评价单位后，研究目标为：

$$\min_\pi\ \mathbb E_\pi\left[\sum_{t<\tau}c(a_t,h_t)\right], \tag{6}$$

τ 是完整输出要求被确定的时刻，不是某个中间变量被解决的时刻。多种模型的 token 不能直接当作同等算力；比较时同时报告分项和同环境耗时。

若存在可靠的观测分布与有限可完成模型，剩余最优成本满足：

$$V^*(h)=\min_a\left[c(a,h)+\sum_o P(o\mid h,a)V^*(h\oplus(a,o))\right]. \tag{7}$$

这定义研究目标，不是第一版已经求出的策略。真实检索可能返回无信息，动作间还共享来源，不满足“一次测试必然准确揭示一个独立变量”的简化假设。第一版不得伪造概率、默认p=0.5再宣称成本最优，也不新增一个模型估计动作价值。小规模有限测试模型可实现精确枚举 oracle，仅用作理论与单元测试参照。[T2]

## 8. 新证据怎样更新或撤销已有结论

每条事实记录变量、值或范围、来源ID、适用实体/时间/情境、父绑定版本以及语义状态。来源存在与语义成立是不同验证层。

新事实兼容时，收紧合法取值范围并重新求值。新事实冲突时，先保留冲突身份；不能把互相矛盾的约束简单合并成空世界，再误判全部输出都成立。必要时撤销有争议的绑定，恢复未决域，并重评实际依赖它的结论。

同一答案有替代来源时，撤销一条路线不自动撤销整个答案。若父实体、值或适用范围改变，依赖旧版本的查询、节点结果和终端证书失效；原文缓存可保留，但不能保留其旧语义结论。

F_t 的大小不要求永久下降。真正的纠错可能使剩余问题重新变大；这不是需要用硬规则掩盖的异常。单调性只在“新增事实可靠且不撤销旧事实”的限定条件下成立。

## 9. 一次完整执行

```text
规划 Q 的输出要求与类型化任务
    ↓
基于当前事实 Γ 化简 F，得到 F_t
    ↓
完整输出已确定？
    ├─ 是 → 检查当前支持与已知反证 → 发布终端结果
    └─ 否 → 取得仍影响输出的活跃需求
                ↓
          选择当前可执行需求
                ↓
          读取待读材料；或执行一次 dense / 原文条件桥接
                ↓
          联合解释材料，得到绑定、引用、冲突与缺口
                ↓
          程序校验，更新或撤销 Γ
                └──────── 回到 F_t 的重新求值
```

伪代码省略协议修复和持久化，但各步骤都对应明确操作：

```python
contract, program = plan_once(question)
state = initialize(contract, program, visible_memory)
while state.budget.can_continue():
    residual = reduce_soundly(program, state.valid_facts)
    certificate = certify_output(contract, residual, state)
    if certificate is not None:
        if validate_current_support(certificate, state):
            return publish_terminal(certificate)
        continue  # 核验更新了事实或暴露了缺口
    active = conservative_live_demands(residual)
    action = next_executable_action(active, state)
    if action is None:
        return incomplete(state, reason="no_executable_evidence_action")
    observations = execute_without_reranker(action, state)
    integrate_source_grounded_updates(observations, state)
return incomplete(state, reason="budget_exhausted")
```

只有读取到新的有效信息或处理了冲突，才能收紧 Ω。一次检索没有新结果不会自动减少未知域。失败重试、无进展和待读状态均需有界并可诊断，不以无限循环假装最终能得到答案。

| m4 | DEL-08针对岚桥V8：文档删除180秒后仍被检索返回。 |
| m5 | 旧版R17要求新增文档2秒内可检索，岚桥旧方案未达到。 |
| m6 | V8新增同步测试的完整记录见SYNC-21。 |
| m7 | V8脱网运行测试的完整记录见OFF-09。 |

### 10.2 第一步：先确定规则和对象，不能先猜判定式

规划先建立“确认当前版本与适用规则”的取证需求。dense 可能返回m1和m5。m5的旧门槛不应直接代入当前问题；桥接以m1中的R17-R2为线索找到m2。

联合读取m1、m2及已见的m5，得到当前版本V8和完整的本次采用规则。到这里才定义：A=新增≤600秒，D=删除≤60秒，O=脱网可用，F=A∧D∧O。规则的范围和三项完备性来自m2，不是由模型补写。

### 10.3 第二步：生成当前尚未确定的检验需求

此时A、D、O均未知，可能的可采用性为{true,false}。这些是逻辑可能性，不是先验概率。三个检验需求都可作用于F；它们并非按顺序虚构出的父子链。

示例中调度轮到D。选择D只是这次固定合法次序的结果，不声称系统提前知道删除测试会失败。用一个不同的顺序仍会得到相同逻辑结果，但访问成本可能不同。

### 10.4 第三步：第一次找到线索，但没有确认 D

以“岚桥V8是否满足删除后60秒不可检索”进行dense，得到m3。一次联合读取只知道存在异常记录和DEL-08线索，没有确切时间；D仍为未知，F_t保持A∧D∧O。

模型不能把“尚有异常”直接等同于“不满足60秒”，也不能把第一次查询没得到具体结果当成D=false。

### 10.5 第四步：沿原文桥接，取得决定性观测

桥接输入为当前删除条件、m3原文、V8与R17-R2绑定、以及必要的前序来源。embedding查询找到m4，同时也可能找到无关讨论；不运行reranker。

该根的子候选池形成{m3,m4,…}。节点模型联合读取必要旧来源和新增原文，确认“删除延迟大于180秒”这一有出处的下界。程序使用同一单位比较，推出D=false。m3与m4共同确定记录归属和观测，m2提供60秒门槛。

### 10.6 第五步：剩余问题直接化简，停止不必要取证

F_t=A∧false∧O=false。对任意A、O的合法取值，采用性都是false，删除失败又能作为一个足够的否决见证。

因此不再为了当前输出继续访问SYNC-21和OFF-09。系统没有认定新增或脱网失败；两者仍然未知。停止是因为其取值已不会改变当前所需输出，而不是因为它们的相关性分数低。

### 10.7 第六步：核验后直接输出

若当前版本、门槛、测试归属和已读反证检查通过，终端发布：

> 目前不能启用岚桥V8。R17-R2要求删除文档60秒内不可检索，而DEL-08记录删除180秒后仍被返回；删除失效条件未达标，单凭这一项已足以否决。本次不需要先查完新增同步与脱网测试才能作出这一判断。

来源保留m1–m4。没有全局候选重选，没有另一个Reader重新回答。已读到的m5作为旧规则被区分，不会混进当前判断。

### 10.8 两个反事实检查

若用户改为“列出所有未满足项”，删除失败只完成部分输出，A和O仍必须求解。若后来确认DEL-08记录其实属于V7，则D=false绑定及终端证书被撤销，D重新未知；系统恢复删除取证，而不是继续发布旧答案。

## 11. 理论结果与可验证边界

### 命题一：条件性停止可靠

假设任务语义准确，真实状态ω*包含于Ω_t，且候选y通过式(4)。则A_Q(y,ω*)为真。

证明：ω*属于全称量化的范围，直接代入即可。若使用外包络，只需真实状态仍在外包络中。这个命题不证明自然语言到约束的映射正确；它将语义误差与控制逻辑错误分开。

### 命题二：安全化简不改变语义结果

对受支持的有限类型算子，若Reduce的每条规则在当前有效约束下等价，则F与F_t对Ω_t中所有状态具有相同输出。

证明：对表达式结构归纳。基本绑定保持值，复合节点只应用等价算子规则，共享变量身份不变。可用穷举小表达式、有限域oracle和属性测试逐项验证。

### 命题三：被化简消去的取证不影响当前输出

若某需求仅用于已经被等价规则消去的子表达式，且不承担其他输出或证书核验职责，则继续确定该需求不会改变当前已确定输出。不能由此推出“相关文档都应删除”，也不能推出访问顺序全局最优。

### 不主张的结果

不把这些基本性质称为新的通用逻辑定理；不宣称任意自然语言任务都可被精确形式化；不宣称搜索全局最优、语义置信度已校准、RAG准确率具有无条件保证。论文增量应由任务求值与记忆访问之间的实际闭环及其效果来支持。

SBFE提供了期望成本调度的理论参照，但其独立变量、已知结果分布和测试可准确揭示结果等条件与真实记忆检索不同。[T2] Sufficient Context表明“上下文足够”和“模型能正确利用”需要分开评估，不能用形式状态替代答案评测。[T3]

## 12. 代码改动与验收重点

| 当前职责 | 新职责 |
|---|---|
| 一次计划后按列表运行节点 | 每次有效观测后重算剩余任务与可执行缺口 |
| 全局原问题基线、末端重选与Reader | 全部取证归属任务；终端结果直接发布 |
| activation式BT | 可暂停、可恢复、零reranker的原文条件扩展 |
| 独立映射再节点求解 | 节点联合阅读一次输出事实、出处、状态与缺口 |
| 所有父项必须supported | 由算子区分短路求值与真正必需的输入绑定 |
| 已有支持版本 | 扩展到剩余状态和终端证书失效传播 |

优先复用`dagbt/engine.py`、`support.py`、`evidence_spans.py`、`proxy_free.py`和现有检索接口。新增最少的类型化剩余求值代码，不重写整个实验框架，不修改冻结vendor、origin或独立dagresolve。[R1–R4]

基准实验至少比较：固定展开的无评分版本；仅终端早停版本；完整的剩余需求驱动版本。固定任务、模型、语料范围和资源，报告终端准确率、错误早停、仍有用但被阻塞的任务、原文访问、生成输入/输出、实际设备时间。包括相同记忆、不同输出契约；同一证据换版本；相同变量重复出现；候选未召回等反事实测试。

真实模型验证前，先用有限世界模拟器证明控制器没有把未知当假、没有把空世界当确定、没有把仅找到的实体当唯一，以及没有偷偷恢复reranker或独立Reader。不要把模拟器测试通过描述成真实准确率提高。

## 13. 最终定位

**我们不是为每个子问题固定扩展若干条记忆链，而是在维护一个尚未完成的求解任务。问题分解指出待确定的变量，桥接访问寻找能确定这些变量的原文，联合阅读产生有来源的新绑定，逻辑化简决定哪些需求仍然必要，终端在完整输出被确定后结束。**

数学首先约束实际的状态更新与停止；成本最优调度是需要进一步假设与实验的研究问题，不用新的提示分数代替它。
