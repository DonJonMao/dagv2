## 1. 要完成的方法，不允许退化成几个提示词

科学问题：**原问题还有哪些结果尚未确定，哪些未决事实会改变所需答案？**

实现一个被所有阶段共享的剩余求解状态：

- 输出契约：用户要求最终给出什么。
- 类型化任务表达式：哪些变量和运算决定这些输出。
- 带来源、范围和版本的有效事实。
- 部分求值后的剩余任务。
- 仍可能影响输出的可执行取证需求。
- 原文候选、已读/未读状态、可恢复的桥接前沿与共享预算。

关键闭环：

```text
一次规划输出要求与依赖结构
→ 对当前事实做部分求值
→ 已确定完整输出则核验后发布
→ 否则取当前仍有作用的可执行需求
→ 子问题 dense / 原文条件桥接
→ 联合阅读，输出事实、出处、冲突与剩余缺口
→ 更新或撤销事实
→ 重新计算剩余任务
```

“还差什么”必须成为程序操作的状态，而不是把自由文本 `missing_information` 放进 prompt 后仍然跑固定层数。停止与任务消去必须实际调用纯代码求值器，并在日志中留下可重放依据。

## 4. 阶段A：输出契约与类型化求解

### A1. 一次规划明确输出要求

复用现有一次planner调用，增加最少的必要schema，至少覆盖：

- `output_contract`：语义输出类型、字段、数量词、实体/时间/情境、解释要求和完成级别。
- `final_node_id`：真正承担原问题输出的节点，不由运行结束时的列表位置猜测。
- 变量/需求定义：ID、类型、是否有界、合法取值域或未知域、参数依赖、来源需求。
- 运算定义：允许的操作与输入引用，不接受任意Python代码。

支持的首版算子至少包括常量、变量、AND/OR/NOT、类型匹配的比较、IF、记录/元组输出、有限失败项集合，以及节点结果引用。数值比较必须校验单位与严格/非严格边界；实体相等不能靠随意字符串模糊匹配。

显式区分取证节点、确定性计算节点与语义综合节点。不要为了统一形式让每个计算节点都执行dense＋BT或多一次生成。

### A2. 规则可能也需要查记忆

对于“是否满足之前确认的条件”，planner不应虚构一个固定条件表。先取回规则及适用范围，再以有来源的方式具体化任务表达式；输出契约保持固定，表达式细化和规则来源必须版本化。

完备性未知时，不能把已经找到的条件当作全部条件，并输出无条件肯定。必要条件失败可以形成否定见证，但该条件确属当前适用规则仍须有依据。

### A3. 开放式任务不要假装精确

有限域/支持算子内的模式可以产生逻辑证书。开放实体域保留未排除值类，开放数值采用保守区间；未知实体不能因为只有一个候选就变成唯一。

无法形式化的自由文本建议，走同一依赖与来源框架的 `semantic_assessment` 模式。不得把它伪装成有限枚举或后验概率，也不得把这部分测试标成形式正确性证明。

## 5. 阶段B：纯代码剩余求值器

### B1. 核心接口职责

实现可离线运行、没有模型调用的操作，例如：

```text
validate_program
reduce(program, valid_facts)
possible_outputs / conservative_output_envelope
live_demands
certify_output
invalidate_dependent_bindings
```

名称可按仓库习惯调整，但职责必须可分别测试。返回的结果应包含剩余表达式、当前绑定、未决需求、输出是否确定、证明依据、版本及未支持原因。

### B2. 未知、冲突、失败语义

布尔未知不是false。未召回、服务错误、格式错误、未阅读或无法判断，都不应产生否定事实。

相互矛盾的事实先进入冲突流程；约束无合法世界时返回 `inconsistent`，不能依据空世界的全称真生成任意答案。

共享变量只保留一个语义身份。有限枚举时维护联合约束；不能分别独立枚举同一个变量在表达式中的多次出现。保守抽象可以不够精确，但不能缩掉真实可能性。

不使用 `eval` 执行模型生成表达式。使用白名单算子和结构化解析。模型提供的短引用ID必须在本次可见原文注册表中存在。

### B3. 停止与输出关系

对于单值函数任务，在合法状态集合非空、且所有合法完成给出同一个结果时产生证书。

对于“给一个决定性原因”等多合法输出任务，验证候选输出在所有当前合法完成中都满足输出契约，而不是要求所有原因完全相同。

“列出全部失败项”必须确定完整集合，不能发现一个失败后就停。原始契约字段/量词不能在中途静默减少。

精确有限枚举超出资源上限时，返回 `indeterminate` 或安全外包络，不把已枚举部分当完整域。现有有限图容量可作为安全后备，但它不是调度质量超参数。

### B4. 活跃需求不能漏掉答案依赖

用经证明等价的化简和结构依赖取得保守活跃集。可以多保留某些需求，不可漏掉仍可能改变输出的需求。

不要直接使用“只改变x，其他变量全固定”的测试处理有联合约束的域。例如约束x=y时，不能因此误判x、y都无用。有限测试oracle用于验证活跃集保守性。

对AND/OR支持短路；对于实体接地和一般语义求解，仍检查真实必需的输入。不得保留旧的无条件“所有父节点supported后才运行任何节点”，使短路只停留在文档。

## 6. 阶段C：将桥接改为可暂停的证据获取

### C1. 当前无评分搜索需要从run-to-budget变为step/resume

现有 `ProxyFreeSearch.run()` 会持续执行到检索额度或前沿耗尽。新控制器需要在一批材料联合读取后重新判断需求，因此提供最小的单步/恢复能力，保存根队列、延续分支、seen状态、查询身份与已用预算。

每次恢复不能重新做dense或重复之前的初始桥接。也不能重置全部预算。允许必要的版本失效导致新查询身份，但须记录原因。

### C2. 桥接条件来自当前未决需求

每个状态明确：需求ID、接地问题、当前线索、路径前序、根归属、适用范围及依赖版本。

检索输入由当前子问题/缺失关系与真实原文拼接，不进行每条边的LLM改写。原问题可以提供约束背景，不得变成额外查询通路。排除当前路径回环，保留不同背景下同一原文的可用性。

### C3. 子候选池只组织原文

根池不分配答案、不评分、不独立调用Reader。不同根找到同一记忆时合并正文并保留多重来源路径。不同根的原文可以共同形成一个事实。

保留发现路径与证明依赖的区别；不要把“查过此文档”强制变成事实必需前提。

### C4. 读取与扩展交替

优先联合读取已取得且尚未解释的适用候选；没有足够信息时，才继续为剩余活跃需求桥接。每批读取返回新绑定/引用、矛盾、未知项，而不是给每篇材料打分。

若一个需求被逻辑化简消去，不再专门扩它的前沿。其旧原文仍可被其他活跃需求使用。已经在当前阅读中发现的反证不得因目标被消去而丢弃。

第一版活跃需求之间采用稳定可执行顺序，需求内部保留明确的根/延续调度。必须在说明里将其称为基线调度，不声称全局成本最优，不用p=0.5或LLM自报概率伪造期望收益。

### C5. 容量与无进展

所有新原文保留已读/待读/遗漏原因。按真实token容量分批；超长记录使用明确的原文分窗和位置，不做隐藏摘要或文本截断。

没有新原文或新绑定不等于需求失败。推进未尝试状态，前沿耗尽/预算不足时返回未完成，不制造false，不无限重试同一输入。

## 7. 阶段D：联合阅读、来源与撤销

复用已有原文片段注册、角色与范围检查。新的节点响应用一个结构化schema同时返回：事实值/区间、来源ID、当前对象和时间范围、实际父依赖、未决字段、冲突。

程序校验的是引用存在、类型、范围、依赖版本及已定义逻辑规则；语义蕴涵仍标记为模型判断，不把引用hash当真实性证明。

允许单次阅读确定多个需求，更新共享变量，但每项事实必须有独立可核对的来源，不因同一次调用出现就自动相互蕴涵。

有替代支持时保留路线身份。父绑定变动后，使依赖旧版本的节点答案、桥接状态和终端证书失效；不要仅改变答案字符串。撤销后剩余任务可以重新变大，不人为限制为单调缩小。

一个事实的候选集合、重复片段和同一消息的多个切片不能伪装成多份独立证据。未知、部分支持、冲突和输入协议错误继续分开。

## 8. 阶段E：终端发布与输出兼容

终端输出由真实输出契约决定，不取最后一个成功节点。确定性结果可由模板格式化，事实型答案已经由节点生成时直接发布。开放式综合在真正终端调用一次模型，标记完成级别。

发布前针对本次证书依赖检查有效来源、版本、适用条件和已知反证。优先利用联合阅读已有核验信息；如保留一次语义审计，计入总预算，审计失败必须更新状态后重新求值，不另起完整RAG流水线。

不让审计无限否决又重试；无进展或预算不足返回未完成。最小证书指足以支持输出的来源闭包，不声称已经求出全局最小自然语言证明。

核心结果字段保持兼容：`answer.status`、`answer.prediction`。新增完成级别（`certified_symbolic`/`semantic_assessment`/`incomplete`）、终端ID、契约身份、有效绑定和证书来源。

`certified_symbolic`只表示条件于语义绑定的程序证书，不表示最终答案经金标证实。保留这一说明于结果metadata与文档。

单选任务公开选项只在真正终端输出时使用，不提前进入检索、桥接或原文映射；金标不进入生成进程。一次终端响应完成语义结果与选择，不新增一个LLM匹配选项；输出解析不放宽。

旧 `budgets[5/10/20]` 如保留只作非生成证据诊断；不能为了这些字段再运行FinalSelector或假装存在Reader输入。更新runner和报告，旧结果可读、新指标不可用时标明，不伪造数据。

## 9. 资源与实验身份

新方法不调用reranker，`set_score_calls=0`，`reader_calls=0`。修改只允许正数的旧校验及不必要的服务预检，不能在无评分模式启动时仍依赖reranker可用。

沿用全题ANN和LLM资源上限作首轮比较，终端阅读/综合计入LLM，不额外赠送reader额度。取消旧全局选择预留，保留完成真正输出和必要核验所需的调用预算。

同一用户记忆范围、截止位置和权限不变。缓存身份包含查询、原文、约束和相关版本；新任务不能偷用旧全局评分或无效事实。

日志至少有：原契约、规则实例化、剩余式、活跃需求、执行动作、已读/未读原文、新绑定/撤销、证书、停止原因、实际成本。每次消去需求能够定位等价规则或结果确定性理由。

不靠大量新的max_x参数构造调度。实际上下文容量、调用额度、后端返回宽度与失败重试可以保留并诚实记录；它们不是证明任务已完成的依据。

`f6a1721`的APC工具保持可用，但新主路径零reranker。旧硬件加速未验证的状态不能改成成功。本轮不重构无用的旧评分服务。

## 10. 必须实现的测试矩阵

### 纯逻辑与属性测试

1. 未知布尔不会变false；无证据不会形成否定。
2. AND中一个false可确定判定；OR中一个true可确定判定。
3. “一个否决原因”与“全部失败项”产生不同停止行为。
4. Ω为空时不认证；有限域枚举溢出不认证。
5. 相同变量重复出现、x与not x、共享子表达式保持一致。
6. x=y等相关约束不被当独立变量，活跃集保持保守。
7. 未知实体保留其他可能性，首次召回不保证唯一。
8. 数值区间/单位换算/边界，如>180秒与≤60秒的矛盾关系。
9. 已有约束变化后重算，不复用陈旧证书。
10. 对小规模有限世界，穷举真值与部分求值/证书逐例一致；使用固定seed的随机表达式和property tests，不只手写三例。

### 来源与控制器测试

11. 规则来自历史时先取证，不预置隐藏答案或完整条件表。
12. 适用版本变动导致绑定和依赖撤销；替代支持可存活。
13. 未读、缺失、无关、协议错误严格区分。
14. 计算节点没有无意义dense或LLM调用；真实取证q=Q合法。
15. 不存在额外Q基线、reranker、FinalSelector或reader/final。
16. 当前需求解决后控制器马上重新求值，不继续旧run-to-budget循环。
17. 需求消去后不再为其取证；不能阻止其原文支撑另一个活跃需求。
18. 一个阅读批次可更新多个共享事实，不重复计算。
19. 持久前沿恢复不重跑dense、不重置预算，同一检索身份不无限重试。
20. 子候选池去重且保留跨池联合支持；查询全程有真实节点归属。
21. 单选公开选项只有终端可见，金标不进入生成，严格解析保留。
22. 缺设备/服务失败标明未完成，不调用模拟答案兜底。

### 必须提供的端到端合成案例

用设计稿的“岚桥V8 / R17-R2 / DEL-08”案例：

- 先检索当前规则，确认三项共同采用条件。
- 删除任务先找到只有DEL-08线索的记录，不能立即判false。
- 桥接找到180秒后仍返回的观测，形成D=false。
- 对“一个否决原因”，A和O不再检索，终端输出带来源的否定。
- 对“全部失败项”，仍继续A、O。
- 把DEL-08改成V7记录，旧D=false不得支撑V8输出。

同时放一个实体链、多父项比较和开放式建议测试，避免整个方法只服务于这个布尔案例。

## 11. 验证与实验，不编造收益

运行新增测试、相关现有回归、冻结目录哈希和 `git diff --check`。提供一个完全离线的合成运行命令，让用户可看到逐步F_t、活跃需求、桥接结果和输出证书。

同环境对照至少包括：固定展开的无评分方法；仅终端早停；完整剩余需求驱动。使用相同语料、模型、固定计划或清楚记录的计划差异、相同资源。消融若改变多个因素需注明，不能叫单因素。

优先报告错误早停率、必要事实遗漏、最终任务准确率/未完成率、每题原文读取量、LLM输入/输出、embedding量、真实设备时间。没有运行真实模型时只报告离线测试，不宣称准确率提升或固定百分比降本。

真实服务可用时按已有授权配置做固定小样本smoke，失败全部保留；不读取金标优化规划、不擅自跑全量、不调整预算掩盖溢出。没有设备或服务时交付可运行代码和离线证据，说明实际阻塞。

## 12. 提交与推送：本任务必须完成的最后一步

按照仓库实际状态执行，而不是机械覆盖已有分支。可参考：

```bash
git status --short
git fetch origin
# 分支已存在时，使用它的远端当前版本，不重新从f6a覆盖。
git switch feat/residual-memory-reasoning
# 本地没有该分支时：
# git switch --track -c feat/residual-memory-reasoning origin/feat/residual-memory-reasoning
```

工作区不干净时使用独立worktree，禁止丢弃更改。阶段性提交建议按纯求值器、控制器与取证闭环、测试与文档拆分，但不强制制造空提交。

完成后只添加明确的源文件、合成数据、配置模板、文档和测试；不要 `git add .` 把私有输出带进去。不能提交token、API key、真实用户原文、原始trace、向量和缓存。

```bash
git diff --check
git status --short
# 完成文件审查后显式git add <paths>，再commit。
git push -u origin feat/residual-memory-reasoning
git rev-parse HEAD
git ls-remote --heads origin feat/residual-memory-reasoning
```

推送前如远端有新提交，正常协调/合并，不force-push；测试冲突解决后的版本。推送后验证远端HEAD等于本地目标提交。未经要求不合并主分支，也不声称已完成生产部署。

最终回复必须包含：新分支与commit链接、修改摘要、实际运行命令、测试通过/失败/未运行项目、离线case的完整状态轨迹、真实模型验证状态，以及剩余实现限制。

交付状态区分：`IMPLEMENTED_AND_TESTED_OFFLINE`、`IMPLEMENTED_AND_SMOKE_VERIFIED`、`PARTIAL_IMPLEMENTATION`或`BLOCKED`，另列`pushed=true/false`。推送了设计稿不等于算法实现完成；通过mock不等于真实语义准确率验证。

## 13. 不接受的“完成”方式

- 只改方法名和prompt，仍按固定层数扩完再统一作答。
- 用模型自报“足够了”替代类型化求值和停止证书。
- 用未知=假、只找到一个候选=唯一、没有反例=条件成立。
- 用增加一层reranker/critic/多agent来掩盖求解状态没有落地。
- 新增一个Bellman公式却仍宣称现有轮换达到了成本最优。
- 为了让数字好看删掉失败样本、未读原文或未完成需求。
- 把文档中的方案当作已完成代码，不运行测试，不验证远端推送。

**最终验收问题：每次检索或阅读是否针对仍会影响完整输出的未决事项？每个停止是否能由当前有效来源和明确任务语义解释？代码必须能回答，而不是仅由论文措辞回答。**
