# 局部证据有效性与下游容量检查

本规则补充 `RESIDUAL_MEMORY_DESIGN_f4e38df.md` 的 6.2、6.3 和 7.3 节。
模型返回的局部事实及反证必须作为整个批次检查、整合；是否能发起下一个
模型调用则由该调用的真实输入、当前依赖和预算决定。两项判断不能互相替代。

## 尚缺父输入的未来目标

`ResidualControl.grounded(target)` 返回 `None` 表示该目标尚缺少可用父绑定。
真实调度器不会执行它。此时根据部分已知父项拼出的输入只是预测；容量检查
可以报告 `advisory`，不能单凭该预测超限，将已经通过局部来源、类型、范围、
父版本、整值一致性等检查的支持改判为 `citation_capacity` 失败。

该规则适用于普通残余求解，不依赖 PersonaMem 题号、变量名称、来源数量，
也不要求新支持的引用恰好是另一项未决义务的子集。集合包含关系只能解释
“缩减这条引用无法减少原文集合”，不能证明缩短整个类型值等其他变化没有作用。

同批反证仍须一起处理。自身支持冲突所触发的当前任务复核，不属于可以忽略的
未来目标；其原有容量检查保留。局部协议错误、缺失真实父版本、非法摘要修订、
整值冲突或未完成失败草稿复核，也不会因为未来目标不可执行而变成合法支持。

## 父输入齐全后的检查

后续观察使父绑定齐全时，必须重新构造下游的完整当前输入并执行既有容量检查。
之前的预测提示不是容量证明，也不是一次审计。真实合成、终端格式生成和审计
继续保留所有当前必要来源、反证及未决复核事项，不拆散必须共同解释的证据。
输出预留、输入余量、模型调用和 JSON 修复预算不变。
父输入齐全但仍存在其他查询的范围或复核权限阻塞时，继续原有检查；本次没有
新增这类阻塞的调度恢复，也不因文本可见就授予跨查询处理权限。

接受一个局部事实不等于允许发布答案。未决事项仍在，程序继续剩余求解；只有
真实终端及相应审计满足既有完整契约后才能发布。容量仍不足时，保持明确失败。

## 状态和恢复边界

预测容量提示只是日志，不加入语义进展签名，不生成新的取证义务或免费重试。
它不清除、合并或降级任何现有义务、失败草稿、反证、探索前沿、已耗尽身份、
来源记录或预算计数。真实观察的整合与版本变化仍通过原有路径产生进展。

一个宽引用的合法事实可能先被保存，而后续完整下游输入无法容纳。当前实现
不会因此自动重写已接受的事实，也未新增跨任务容量修复队列。后续能否合法
补证或复核仍受已有任务、来源、父版本及预算规则限制；否则如实停止。
该政策纠正事前预测与局部事实有效性混用，不保证所有任务均可在固定容量完成。

## 验证要求

回归需覆盖未绑定父项时合法支持保留、同批反证、父项补齐后的严格容量拒绝、
自身冲突复核、真实终端与审计、恢复后的义务/来源/版本，以及日志不产生进展。
离线回归不能证明模型回答正确；修改后的源码须使用新的固定题组运行身份验证，
不能回填旧失败结果或用旧运行代替新源码验收。
