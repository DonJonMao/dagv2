# Residual：探索前沿与证据义务

本策略区分发现状态、实际阅读工作与已观察证据义务。它修订旧实现将普通读取
队列全部作为发布阻塞的保守策略；不改变原输出契约、条件性证书或开放语义
评估的保证。实现和验收以对应提交、完整测试及新运行记录为准。

## 理论依据

`RESIDUAL_MEMORY_DESIGN_f4e38df.md` 的 2.2 节区分事实状态、已发现/已读/待读
状态与可恢复前沿；4.2、5.3 节要求得到新证据后重新求解剩余任务。发现一份
原文不是建立一个语义约束，保留候选也不等于声明它无关。

6.2 节要求同一实际响应的事实和反证一起处理；6.3 节要求真实容量检查与待读
范围留痕；7.3 节要求对采用的支持与已知相关反证进行审计。这些规则不要求
读完所有检索候选之后才能利用当前充分支持，也不授权忽略已观察的问题。

## 三种状态

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| 纯探索前沿 | 有明确发现来源、尚未实际尝试判读，且没有已知必要取证关系的候选 | 可暂停并恢复；不绑定事实，不直接产生发布阻塞 |
| 已尝试未完成工作 | 已进入实际阅读/修复，但请求、槽位、来源或草稿未完成合法处理 | 保留 owner 与失败状态，按既有付费恢复规则处理 |
| 必要证据工作 | 当前证明共同前提、规则完整性、明确定位线索、带源未决问题、失败草稿或相关反证所要求的材料 | 即使尚未发送也不能按纯候选豁免 |

分类需要可核对来源。无法区分的旧记录保守保留为阻塞工作；不能在容量检查
失败后将必要原文重新命名为探索前沿。新查询身份不能洗掉旧义务。

调用方通过 `discovery_doc_ids` 显式声明本次普通检索的候选来源。默认 `None`
保留旧的硬义务语义；父证据文档不能仅因同时出现在输入列表里就被宣称为普通
候选。`unoffered` 以记录中的 query、task、作用域及版本为范围，不能解读为
该原文在整次运行中从未出现；过去的实际请求及未完成义务分别保留。

## 读取与重新求解

普通检索窗口每次完成一个实际批次后交还控制器。必须先校验全部请求槽位、
实际出现的草稿和反证，完成允许的修复，再整合事实并重新求解。第一条 support
不授权提前返回。失败或未决事项继续存在，后一个成功批次不能自动解除它们。

仍有活跃需求时，按原顺序恢复已有候选与桥接前沿；不因函数返回就重新执行
dense 初始化或重置预算。发现、排队、改名或暂停标记本身不能制造新的语义
进展或新的修复资格。新反证、作用域或父版本变化仍使旧依赖失效。

mandatory 合成与审计继续单次提供本次必要的完整原文闭包。不能把必要共同
前提拆成多个成功前缀，也不裁剪当前摘要累计来源、反证或复核材料。

## 输入可见范围与语义接受

程序记录完整实际请求范围，包括窗口邻接、父来源、失败复核和修复材料；
不能只记录主窗口 alias。未引用不等于未发送，已进入请求的原文不能因未被
引用而退回从未尝试的前沿。请求失败或状态不明时，保留尝试及成本记录。

沿用完整 required slots、整响应校验和显式未决/失败的既有协议；不新增独立
映射模型或要求每条原文逐一分类。一个合法完整响应是有条件的语义接受，
不证明模型没有漏读未引用的反证，也不把未引用原文记为无关。

## 发布与恢复

符号 certificate 仍以合法当前绑定、固定契约、非空允许世界、规则完整性及
实际依赖无阻塞义务为条件。纯候选队列不替代未知变量取值，也不提供完整性
证明。“全部失败项”、全集、全称、缺失、最新等输出仍须满足原有契约。

开放任务仍需真正的终端回应与审计，完成级别保持 `semantic_assessment`。
历史 support 不能直接发布为最终回答，候选暂停也不能被描述成“未读原文
不可能改变答案”。新证据改变绑定时，保留的前沿必须可重新参与求解。

快照保留来源、owner、变量/版本、实际尝试、未完成义务、预算和前沿顺序。
旧快照只有泛化 unread、缺少分类依据时继续按旧阻塞语义恢复。停止策略变化
需要新的实验身份和目录，不能套在旧运行中继续写结果。

新增前沿和曝光记录随 `joint_reading` 诊断及 checkpoint 一同保存。请求记录
区分已返回、失败和未发送；程序记录的尝试范围不证明服务收到了所有文本。
这些记录及单纯排队不会单独构成求解进展，不能刷新重试权限或预算。

恢复时以稳定原文 ID 和完整原文身份核对来源。临时 alias 可以重新编号；可执行
前沿、已读索引和来源义务按保存的来源映射重绑定，实际旧请求的 alias 与请求
身份则保留，并另记当前绑定。改动原文、角色、时间或邻接信息不能被当作一次
合法编号变换；编号变化本身也不能制造新证据进展或额外重试资格。

执行完成率、未评估候选范围、实际证据覆盖、成本和答案准确率分别报告。
离线协议测试或执行成功不证明答案质量，也不保证所有必要闭包都能放入 16K。
