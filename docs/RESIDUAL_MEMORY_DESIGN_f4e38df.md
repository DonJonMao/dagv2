# 剩余求解驱动的记忆推理

## 基于 f4e38df 的增量设计

**设计版本：v2 · 2026-10-10**  
**代码基线：`f4e38df23b5b621a4d0e759c018c60e1fe25dd9b`**  
**基线方法：`dagbt_local_terminal_v1`**  
**拟实现方法：`dagbt_residual_memory_v1`**  
**工作分支：`feat/residual-memory-f4e38df`**

核心问题是：**原问题还有哪些结果尚未确定，哪些未决事实会改变用户要求的最终输出？**

DAG 分解、记忆桥接、节点阅读和终端输出共同维护一个剩余求解任务。系统不以“所有规划节点都执行过”“候选池已经足够大”或“调用预算用完”为完成依据，而是判断当前还有哪些信息值得继续查明。

本文是从已核对代码出发的待实施设计。三项前序修复直接继承，不重新实现；本轮增加无评分桥接、联合阅读和程序化剩余求值。配套实施要求见 `CODEX_GOAL_RESIDUAL_MEMORY_f4e38df.md`。

## 1. 起点已经改变，本轮只做增量

### 1.1 f4e38df 已具备的基础

`f4e38df` 是三项修复及其验证材料所在的代码快照，其中 `dagbt_local_terminal_v1` 已具有以下行为。[R1–R4]

| 基础机制 | 本轮如何处理 |
| --- | --- |
| 没有游离于 DAG 的原问题 dense 基线 | 直接保留。单个真实子问题恰好等于原问题仍可正常检索。 |
| BT 按接地子问题评分，查询与父绑定版本进入缓存身份 | 保留在基线方法中供对照。新方法取消 reranker，不再重复改造评分器。 |
| `final_node_id` 显式指定终端 | 直接继承，扩展终端的程序求值方式，不再按列表位置猜答案。 |
| 节点区分 `retrieval` 与 `compose` | 直接继承；进一步区分确定性组合与必须由模型完成的语义综合。 |
| 终端同次求解生成答案，独立 Reader 和 FinalSelector 均为零 | 直接保留，不恢复任何末端重答。 |
| 支持来源、父版本、替代路线、输出格式身份与审计 | 复用并扩展到剩余任务和终端证书。 |
| 新结果 `budgets={}`，终端输入与支持闭包分别统计 | 保持语义，不恢复旧的 k=5/10/20 Reader 选文指标。 |

**局部评分已完成，与新方法将评分取消，并不矛盾。**前者是已实现基线的一部分；后者是之后确定的研究设计。新旧方法应并存，以便说明收益分别来自删去重排、合并阅读和改变求解控制。

### 1.2 本轮真正新增的内容

本轮将“固定任务逐个执行”推进为“每次证据更新后重新检查剩余任务”。实际新增四件事：类型化输出契约与剩余求值；可暂停的零评分桥接；单次节点阅读同时形成事实与来源；按剩余输出需求推进、消去和停止。

现有 `ProxyFreeSearch` 已提供无评分的原文条件检索，但其 `run()` 主要持续执行到额度或前沿耗尽。它是可复用的起点，不是已经完成的剩余求解控制器。[R5]

### 1.3 基线验证说明了什么

仓库记录报告了 730 项离线测试通过，但固定六题真实 smoke 没有产生受支持的成功预测；记录中出现输入视图省略、mapping 不完整、来源协议错误和审计未完成。六题共记录 1,951 个集合评分单位。这些是基线报告，不是本轮重新运行的结果，也不能当作稳定任务的平均成本。[R6]

因此，新方案不能只删 reranker，再增加一份更复杂的 JSON。联合阅读应减少重复判读和无关状态输入，修复请求也要按实际容量分批；不能靠放宽引用校验、扩大预算或恢复 Reader 兜底制造成功。

## 2. 统一对象：用户要求的输出与尚未完成的求解

### 2.1 先确定“回答到什么程度”

三个表面相近的问题，对应不同的停止条件。

| 用户请求 | 必须确定的内容 |
| --- | --- |
| 方案是否可采用？ | 可采用性判断。 |
| 不能采用时，给出一个决定性原因即可 | 判断，以及一个足以否决的、有来源的原因。 |
| 列出全部不满足的条件 | 判断，以及完整的失败条件集合。 |

同一条失败证据可以完成前两种任务，却未必完成第三种。系统必须固定原问题的语义输出要求，不能在发现一个容易回答的局部问题后，悄悄减少用户要求。

输出契约记作 $K_Q$，包括所需字段、类型、数量词、实体与时间范围、解释要求。它不等同于面向单选任务的公开选项；选项仍只在终端格式化阶段可见。

### 2.2 一个贯穿流程的变量

令 $F$ 为任务的类型化求解表达式，$\Gamma_t$ 为第 $t$ 次更新时仍有效的、带来源的事实约束。核心变量是：

$$F_t=\operatorname{Reduce}(F,\Gamma_t). \qquad (1)$$

$F_t$ 表示已经把已知事实代入以后，还必须完成什么。它既可以包含实体绑定，也可以包含条件组合、比较、集合构造或尚未取得的规则。

| 符号 | 含义 |
| --- | --- |
| $Q$、$K_Q$ | 原问题及固定输出契约。 |
| $F$、$F_t$ | 完整求解表达式及当前剩余表达式。 |
| $\Gamma_t$ | 有效事实、范围、引用和实际依赖；包括版本。 |
| $\Omega_t$ | 当前证据允许的未决变量联合取值，或其安全外包络。 |
| $C_t$ | 已发现原文及已读、待读、读取失败等状态。 |
| $H_t$ | 可恢复的桥接前沿，每个状态归属于具体需求。 |
| $B_t$ | 全题剩余资源，不是答案是否已确定的指标。 |

系统状态可写为 $(K_Q,F_t,\Gamma_t,C_t,H_t,B_t)$。候选池大小、模型自报置信度和缓存命中率均不是这个求解状态的替代品。

### 2.3 规则本身也可能需要检索

“是否符合之前约定的条件”不能在规划时凭空变成一个完整条件表。先建立找回规则的需求；找到适用规则及出处后，在同一计划内实例化相应表达式。

例如，初始表达式可以保留“采用规则”这个未绑定输入。取得原文后，才展开为若干必要条件的 AND。**输出契约保持不变，内部表达式的实例化单独记录 `program_revision` 与规则来源**，不能覆盖既有 `requirements_hash` 来隐藏改题。

内部逻辑变量和廉价运算节点不等于新增付费子任务。实际取证需求仍受已有节点与调用额度约束；条件过多时可由一次有界阅读更新多个变量，不能借规则展开绕过预算或静默删掉多余条件。

## 3. 数学如何真正控制停止与继续

### 3.1 未知不是假，也不是“没有找到”

布尔变量未知时，可能值为 $\{\mathrm{false},\mathrm{true}\}$。无召回、未阅读、服务失败或无效 JSON 都不能产生 false。`status=supported` 表示某个值有支持，因此受支持的值完全可以是 false；状态与布尔值不能混为一谈。

开放实体域中，“只召回一个名字”不表示其他名字被排除。明确、适用的原文可以支持单值绑定，但候选数量本身不行。开放数值可用带单位和端点开闭信息的区间表示。相关变量必须共同约束，同一变量重复出现仍是一个变量。

已知冲突应保留并处理其来源，撤销或暂挂有争议的约束。若求值后确实没有合法状态，返回 `inconsistent`，不能从空集合上的全称真认证任意答案。

### 3.2 单值任务的停止条件

对有明确语义函数的任务，可能的终端结果为：

$$\mathcal Y_t=\{F(\omega):\omega\in\Omega_t\}. \qquad (2)$$

若存在合法状态，且所有合法完成给出同一结果，则剩余未知已不能改变这项输出：

$$\Omega_t\ne\varnothing\ \land\ \operatorname{card}(\mathcal Y_t)=1. \qquad (3)$$

其中 card 表示集合中的结果数量。实现不必枚举任意规模的世界。第一版采用有证明依据的局部化简和保守抽象；必要时用小型有限域枚举验证。计算出的结果外包络 $\widehat{\mathcal Y}_t$ 必须包含真实可能结果：它为单值时可以认证，多值时继续；超出计算能力时返回未定，不用部分枚举冒充完整枚举。这借用抽象解释的安全近似原则，不声称发明该理论。[T1]

### 3.3 多个回答都合法时，验证一个足够的输出

“给一个否决原因”不要求所有可能世界具有完全相同的全部解释。令 $A_{K_Q}(y,\omega)$ 表示输出 $y$ 是否满足世界 $\omega$ 下的固定契约。可以发布 $y$ 的条件为：

$$\Omega_t\ne\varnothing\ \land\ \forall\omega\in\Omega_t,\ A_{K_Q}(y,\omega)=\mathrm{true}. \qquad (4)$$

这个关系由白名单输出算子实现，不再请一个模型随意打分。已确认必要条件 $D$ 失败时，“不能采用，因为 $D$ 失败”可以是合法输出，即使其他条件仍未知；要求全部失败项时则不能停。

对需要所有条件成立才能肯定的任务，规则是否完整也必须有证据。一个适用的必要条件被反驳，通常足以否定；仅把已找到的几项全部验证通过，不足以证明不存在其他门槛。

### 3.4 真正改变 DAG 的地方

假设当前规则已确认是 $F=A\land D\land O$。当 $D=\mathrm{false}$ 时：

$$F_t=A\land\mathrm{false}\land O=\mathrm{false}. \qquad (5)$$

此时如果输出只需判断和一个原因，就不再为 $A$、$O$ 专门取证。但两者仍然未知，不是被判假。若输出还包含全部失败项，则未完成的集合表达式继续依赖它们。

**f4e38df 的通用执行检查仍要求声明父节点全部受支持。这个规则要保留给实体接地和一般语义任务，但不能套在确定性 AND/OR 节点上。**否则短路只发生在文档中，代码仍会先查完所有父节点。[R2]

### 3.5 理论边界

停止证书的条件性结论是：若真实状态没有被语义解释和抽象计算错误地排除，且输出通过式（4），则该输出满足规定任务。等价化简可用结构归纳和有限世界属性测试验证。

它不证明 LLM 永不误读，不证明语料没有尚未检索到的反证，也不自动给出全局最优访问顺序。开放式偏好建议可沿同一依赖流程处理，但完成级别记为 `semantic_assessment`，不得伪造有限域逻辑证书。上下文充分与模型正确利用上下文仍应分别评估。[T3]

## 4. 一次新流程如何运行

### 4.1 规划与初始化

沿用一次规划以及 `final_node_id`、`retrieval/compose` 的已有结构。增加最少的类型、输出契约和确定性运算描述，不新增一轮独立“元规划”。模型不得返回可执行 Python；程序仅解析有限的合法结构。

对于自然实体链，已有最后一个取证节点即可是终端。对于比较或条件组合，`compose` 若有受支持的确定性运算，由程序求值；其他语义综合保留一次必要的终端模型调用。

### 4.2 每次先更新剩余任务，再决定下一个付费动作

根据当前有效事实求值，得到剩余表达式与保守活跃需求集合。活跃需求是“仍可能影响所需输出或其必要来源核验”的需求，不是“计划里还没执行过”的全部节点。

化简可以多保留某些暂时判断不出的需求，但不能漏掉仍有作用的依赖。联合约束存在时，不能仅测试“保持其他变量不变，改变一个变量”，就认定变量无用。例如 $x=y$ 时，必须尊重二者共同变化。

### 4.3 读取、取证、桥接与再求值交替

```text
一次规划输出契约与任务依赖
    ↓
用有效事实化简剩余任务
    ├─ 结果已确定 → 核验当前依据 → 终端发布
    └─ 尚未确定 → 找到仍有作用的可执行需求
                        ↓
                 读取待处理原文，或取得新材料
                        ↓
                 联合解释，更新事实、冲突与缺口
                        └──── 回到剩余任务求值
```

预算仅控制能否发起下一个检索或生成请求。最后一次允许的阅读已经得到决定性结果后，即使额度归零，也必须允许免费化简、证书校验和发布。尚需模型审计时则仍要有真实预留额度，不能把付费核验当免费。

## 5. BT 改为可暂停的原文条件化桥接

### 5.1 首次 dense 与后续桥接

当前活跃需求先使用已确认的父结论构造具体问题。首次访问时执行一次 dense。取得候选后先允许节点阅读；仍有缺口时，再用真实原文进行初始桥接或条件扩展。**不能先调用一次会扩满初始池的旧接口，才把控制权交给剩余求值器。**

桥接状态记为 $(i,r,m,P,\nu)$：$i$ 是需求身份，$r$ 是初始起点，$m$ 是当前线索原文，$P$ 是分支前序原文，$\nu$ 是绑定与程序版本。输入由当前具体问题、未解关系、$m$ 和必要的 $P$ 确定性构造，调用 embedding 和可见语料检索，不额外调用聊天模型生成每条查询。

现有条件检索具有按问题、目标原文和前提原文发起查询的接口，可复用；新控制器要管理暂停、恢复和版本，不能只把 `proxy_mode` 改成 `none`。[R3、R5]

### 5.2 多个子候选池如何使用

每个 dense 起点有一个发现池，接收该起点沿各分支发现的候选。不同池允许重合；正文按原文身份去重，保留多重发现路径。池仅用于组织和追溯，不分配独立答案，也不各自调用一次 Reader。

同一需求的联合阅读可以同时使用不同池中的材料。无评分不等于无排序，桥接仍使用向量检索返回的顺序；但没有四项测量、候选对的集合评分、评分门控或评分驱动的 pivot。

前沿中的检索状态按完整查询语义去重，不只按文档 ID 去重。同一记忆在不同前序条件下可能需要不同查询。已发现原文不是已证明事实，路径也不是支持关系。

### 5.3 不再运行到预算耗尽才返回

提供单步推进和恢复语义，一次推进取得一个现有接口定义的候选批次即可返回控制器。控制器组织读取，更新 $F_t$，再决定是否继续。恢复不得重跑已经完成的 dense、已完成的初始桥接，也不得重置预算。

需留意旧 `propose()` 在未建立初始池时可能自动触发初始扩展。适配层应显式维护初始化状态，保证一次推进实际只发生预期的检索，不修改冻结 vendor。

### 5.4 第一个可实现版本怎样调度

活跃需求之间采用确定、可复现的可执行顺序；同一需求内部沿用明确的起点/延续轮换与本地检索顺序。**形式保证来自活跃需求的安全消去和输出判定，不来自这个基线调度达到最优。**

暂停需求时保留其前沿。如果反证撤销了一个决定性绑定，应重新激活相关需求；不能因为曾经被短路就永久删除它。被消去的是当前无需完成的任务，不是所有相关原文的访问资格。

## 6. 用一次联合阅读替代 mapping 后再求解

### 6.1 模型负责解释，程序负责计算

现有流程先把原文映射为节点证据，再调用节点求解。新流程让同一次局部阅读返回：事实值或范围、实际引用、适用实体/时间、真实父依赖、尚未完成的字段和已知冲突。来源注册、准确文本位置、引用校验和版本检查继续由程序执行。

不对整题所有原文与所有节点构造全量交叉映射。不让每个子池单独生成摘要，再增加一个汇总模型。一次批量阅读可更新多个共享事实，但每项更新必须具有可核对出处。

### 6.2 未完成事实与有效证据分开保留

模型未能形成最终事实，不意味着该原文无用。已有线索、定位信息和合法引用可保留供后续桥接。格式无效、语义未知、明确无关、尚未读到是四种不同状态。

一个阅读批次中的有效事实和反证应先作为同一批观测校验、整合，再统一求值。不能处理到第一条有利事实就发布，从而漏掉同一响应后面的冲突。

### 6.3 解决真实容量问题，不用增加隐藏工作

读取输入只包含当前需求、必要父结论与来源、当前待判原文及相关已知反证。按实际 wire 模板、输出预留和修复余量计算容量，正文过长时显式分窗或拆批，记录待读范围。

第二批读取可以重现与新材料共同解释所必需的旧原文，但不无条件重传全部历史。修复响应只处理失败字段；冻结之前的合法记录，重新检查修复后的容量。不能凭固定安全系数猜测一定能容纳，也不能通过省略关键反证让证书通过。

这直接回应 f4e38df 记录中的修复请求溢出和大批映射失败，但是否改善真实结果需要重新验证，不能由设计直接保证。[R6]

## 7. 事实版本、逻辑证书与终端发布

### 7.1 来源与规则共同构成证书

证书保留实际使用的事实及来源、父版本、规则来源、输出契约身份、表达式版本和化简步骤。它说明为什么当前输出不再需要某些未决项，不是另一份没有出处的推理摘要。

符号计算产生的终端应带 `derivation`，语义模型产生的终端应带实际响应身份。**不能为了通过旧发布器必须存在 `terminal_input` 的检查，伪造一条终端模型响应。**应显式区分程序推导与语义求解的合法发布依据。[R2]

### 7.2 冲突、撤销与恢复

父实体、值、范围或所采用规则变化后，依赖旧版本的事实、桥接任务和证书失效。原文仍保留，语义绑定必须重新确认。有独立替代支持时，不因一条路线失效就撤销全部结论。

冲突处于无关任务中，不应自动使所有答案失效；与当前证书、规则或实际依赖有关的冲突必须处理。保留来源作用域与不一致状态，避免全局“只要一个字段未知就不能回答”，也避免空世界推理。

剩余任务允许重新变大。单调收缩只在有效新增事实不撤销旧事实的条件下成立，不用强制单调规则压住纠错。

### 7.3 审计与直接输出

继承基线的“核验后发布”原则。程序先核对实际来源、绑定版本和计算推导；语义审计针对当前输出采用的支持及已知相关反证，按需要计入真实预算。不要求所有已检索原文都先完成与所有规划节点的映射。

审计未完成的相关支持不能被当作通过；无关节点未解不能自动否决一个已有充分依据的输出。核验后再次计算剩余任务和证书，防止审计修改了事实但发布旧答案。

确定性结果可直接格式化；开放式综合只在已有真正终端完成所需生成。单选的公开选项只进入最终输出阶段：可确定匹配时程序转换，否则由真正的终端语义调用同次完成，不能新增独立选项匹配模型或向上游泄露选项。

### 7.4 输出协议保持兼容

继承 `answer.status`、`answer.prediction`、`answer_source=dag_terminal`、`final_node_id`、`output_identity` 和来源闭包。扩展 `completion_kind`、`program_revision` 与 `certificate` 等必要字段。未成功预测仍为空，不强行输出最后一个成功节点。

`budgets={}` 与旧 Reader 指标不适用的语义继续保留。若符号终端没有模型输入，`terminal_input_doc_ids` 不伪造；新增证书来源字段解释实际依据。程序规则可以进入推导记录，但不能冒充语料文档或可检索记忆。

## 8. 统一成本目标与可证明边界

令 $h_t$ 为截至第 $t$ 步的实际观测历史，动作 $a_t$ 为一次必要取证或读取，$c(a_t,h_t)$ 是它的真实费用或设备时间，$\tau$ 是完整输出被确定的时刻。研究目标是：

$$\min_{\pi}\ \mathbb E_{\pi}\!\left[\sum_{t<\tau}c(a_t,h_t)\right]. \qquad (6)$$

目标策略必须完成所定义任务；不能把永不回答、立即拒答当作零成本最优。预算不足的未完成率与成功任务成本一起报告，不只平均成功题，也不把不同模型的 token 直接等同为算力。

有可靠观测模型时可以研究剩余期望成本递推；但第一版没有这样的模型，不引入 LLM 自报概率、小 reranker 或默认概率来伪装最优调度。随机布尔求值理论提供成本目标参照，不能直接把其独立测试假设套到相关、多记录、可能无结果的记忆检索上。[T2]

第一版应可验证的性质是：化简不改变合法完成下的语义；已认证输出在当前假设下满足契约；安全消去的需求不再是该输出必需的取证项；撤销会使受影响证书失效。这些基本性质服务实际控制器，不当作全新通用逻辑定理宣传。

## 9. Case study：恢复岚桥 V8 同步方案

**以下材料和执行顺序全部虚构，用来演示机制，不是实验结果。**

用户问：**“根据本次演示验收要求，岚桥同步方案现在可以启用吗？不能的话，给一个足以否决的条件即可。”**

### 9.1 可访问的历史

| ID | 原文内容 |
| --- | --- |
| m1 | 本次演示采用岚桥 V8，适用 R17-R2，不再沿用旧版 R17。 |
| m2 | R17-R2要求新增600秒内可检索、删除后60秒起不得再被返回、脱网可用；三项同时满足即可启用，无其他门槛。 |
| m3 | 岚桥 V8 删除测试存在待查异常，具体复现见 DEL-08。 |
| m4 | DEL-08针对 V8：同一被删文档在删除后180秒的检索请求中仍被返回。 |
| m5 | 旧版 R17 要求新增2秒内可见，旧方案未达标。 |
| m6 | V8新增测试记录见 SYNC-21。 |
| m7 | V8脱网运行记录见 OFF-09。 |

### 9.2 先查对象与规则

一次规划指定真实终端及输出契约，只建立“确定当前版本与适用规则”的取证需求，不提前猜三个门槛。dense 返回 m1、m5；阅读确认版本是 V8，旧规则不适用，R17-R2 的内容仍未知。

以 m1 的规则标识桥接，取得 m2。一次联合阅读把版本绑定、规则内容、适用范围及来源写入事实状态。此时才实例化 $F=A\land D\land O$，三项仍未知，采用性可能为真也可能为假。

### 9.3 当前需求取得线索后，不立即假定结果

示例调度先处理删除条件 D。这只是预定合法顺序，不声称控制器预知哪一项会失败。接地子问题是“岚桥 V8 是否满足删除后60秒起不得再被检索返回”。dense 找到 m3。

阅读 m3 只得到 DEL-08 这个线索，没有足够信息判定 D=false。剩余表达式不变；节点保留未解关系，控制器继续这一需求的桥接。

### 9.4 桥接与阅读补全决定性观测

查询由当前删除要求、m3 全文、V8与R17-R2绑定及必要来源构成，经 embedding 找到 m4。不同起点发现的候选在当前需求内去重联合读取，不做四项评分，不先为每个池生成答案。

模型确认的是“180秒时仍返回”这一原文观测。程序将它作为“60秒及以后不得返回”规则的反例，得到 D=false。这里不推出删除延迟恰好180秒，也不需要假定删除过程单调。

### 9.5 化简后停止无必要访问

$F_t=A\land\mathrm{false}\land O=\mathrm{false}$。用户只要求一个决定性原因，删除失败已经是合法见证。因此不再为当前输出访问 SYNC-21 和 OFF-09；A与O仍标为未知。

来源、版本、适用范围及已知反证核验完成后，程序终端直接输出：“不能启用岚桥V8；当前规则要求删除后60秒起不得被返回，而DEL-08记录在180秒时仍有返回，删除条件已被违反。”

| 时刻 | 状态变化 | 下一步 |
| --- | --- | --- |
| 仅有问题 | 版本、规则、符合性均未知 | 查适用规则。 |
| 读到 m1 | V8、R17-R2已绑定 | 沿规则名桥接。 |
| 读到 m2 | $F=A\land D\land O$ | 查一个仍有作用的条件。 |
| 读到 m3 | 只有 DEL-08 线索，D未知 | 继续删除需求桥接。 |
| 读到 m4 | D=false，F=false | 核验当前否决依据。 |
| 核验完成 | 输出及一个理由已确定 | 终端发布，不重读全题。 |

### 9.6 必须同时通过的反事实

用户改问“列出全部失败项”时，删除失败只完成部分输出，A与O继续取证。若 DEL-08 被纠正为 V7 的测试，旧 D 绑定与证书失效，删除需求恢复；不能发布适用于 V7 的 V8 结论。

普通实体链则表现为逐步绑定查询对象、减少未决参数，而不一定具有短路收益。开放式建议仍以事实和依赖组织求解，但不假装存在可穷举的唯一自然语言答案。

## 11. 评测与实施门槛

基线比较以 f4e38df 的 local-terminal 为起点，不再以 f6a1721 的独立 Reader 流程作为唯一参照。至少依次检查：带评分基线；无评分但其他节点处理不变；无评分联合阅读；完整剩余求解控制。前三者用于拆分开销来源，最后一对重点验证任务消去和停止，不把多因素变化伪装成单一创新收益。

离线测试覆盖未知/假区分、空世界、共享变量、单位边界、一个原因/全部原因、版本撤销、零reranker、单节点q=Q、真实终端、选项隔离和预算恰好耗尽后的发布。小型有限世界枚举用于验证控制逻辑，不能替代真实模型效果。

真实 smoke 优先使用基线固定的三道QA与三道个人历史题、单次尝试、相同范围和资源，完整保留失败。不新增预算、不放宽引用、不猜选项。把未读、容量不足、协议错误、语义未知、冲突和证书未完成分别报告。未发现算法错误但六题仍无成功时，也要如实给出，而不是将离线通过写成真实验证成功。

发布到新分支的是代码与测试，不自动部署生产。基线分支与旧设计分支均不改写；新方案的成本和准确率必须由它自己的运行结果支持。
